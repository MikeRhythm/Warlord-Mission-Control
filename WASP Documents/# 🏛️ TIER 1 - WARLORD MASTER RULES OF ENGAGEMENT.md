3. MULTI-AGENT STACK & SECURITY CONTROLS
ACCESS ISOLATION: Under no circumstances are execution agents to be granted root or sudo access levels. All runtime engines must operate on dedicated, unprivileged accounts or isolated environments.

CREDENTIAL ISOLATION: System agents are strictly barred from logging into personal Google, Apple, or password-manager profiles. Enforce a complete firewall between individual consumer profiles and automated agent workspaces to eliminate cross-contamination of access tokens.

DOCKER SANDBOXING: OpenClaw environments executing raw terminal commands, filesystem alterations, or external browser interactions must run utilizing Docker sandbox containment modes to prevent untrusted execution branches from touching the host machine.

API BUDGETING & FINANCIAL GUARDRAILS: To prevent agents from draining token allocations on exploratory, repetitive, or circular tasks, hard usage caps and maximum API cost thresholds must be strictly configured within the core provider accounts (Anthropic, OpenAI). Paperclip must explicitly monitor task loops. If a task sequence triggers runaway tool calls, the engine must freeze execution and await human verification.

SESSION MANAGEMENT & STATE RECOVERY: Workflows must heavily leverage Paperclip's checkpoint-based recovery structures. If an OpenClaw agent or Hermes tool adapter drops a connection or encounters an environment fault mid-run, the task must resume from the last saved state checkpoint rather than re-initiating from scratch. Tasks must be provisioned with explicit boundary constraints. If an agent hits an edge case not handled by its instruction set, it must not make unilateral structural decisions. The edge-case error must be surfaced, and the specific skill definition must be refined by Mike before proceeding.

OPERATIONAL OVERSIGHT & ESCALATION: Avoid "approval theater." Human authorization loops must never blindly click "approve" on step-by-step agent heartbeats. The human reviewer must check the actual trace log data, tool arguments, and sequential logic before validating an execution branch. Every automated role or sub-agent assigned inside Paperclip must map to a designated human lead. If a workflow stalls or encounters an unhandled exception, it must escalate directly to the designated owner for explicit parameter tuning.

AGENT SEPARATION & PRIVACY BOUNDS: Shared OpenClaw or Hermes agents are strictly limited to team operations inside identical, verified boundaries of trust. Agents possessing access to critical keys, local databases, or trading accounts must remain private and decoupled from shared multi-user streams.

4. STRICT ARCHITECTURAL & COMPILATION PROTOCOLS
ZERO-STATE INITIALIZATION: Every script, runtime engine, multi-agent workflow, or server layer must initiate from a hard-purged, completely clean state window. No residual variables, un-invalidated caches, active session state data, or temporary network links may bleed across reboots or task loops. All memory pointers, variable stores, and data structures must be explicitly instantiated to null, zero, or baseline configurations on boot to definitively prevent NaN memory contamination.

ATOMIC STAGE COMPILING: Software updates, asset alterations, trading logic configurations, and system modifications must proceed exactly one file, one module, or one functional block at a time. The system must halt and verify compilation integrity at the current stage before proposing, processing, or editing any code or configuration further down the deployment chain. Multi-stage compound refactoring without immediate localized validation is strictly prohibited.

FULL-ARTIFACT DELIVERY FORMAT: Every technical output—including batch files, automation scripts, MQL modules, and environment configurations—must be written out and delivered in its entirety as a complete, self-contained, ready-to-execute asset block. The use of truncated snippets, ellipses (...), comment-based block preservation markers (e.g., // Keep existing logic here), or partial diffs represents a structural failure. Every file must be written out completely, from line one to the final statement, every time.

ABSOLUTE LOCAL PATH MANDATES: The system must never refer to file locations or file operations using relative path routing or generalized naming patterns. Every single file tracking, editing, execution, or generation request must explicitly state its absolute on-disk directory tree mapping (e.g., B1:\Rhythm_WASP\packages\mcp-server\src\index.ts). When instructing file interaction or directory switching, the full, raw console or Explorer navigation commands must be completely provided.
